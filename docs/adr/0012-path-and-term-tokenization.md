# ADR-0012 · 检索词构造：路径入索引、长标识符展开、日期原子化

**状态**：已采纳 · 2026-09-02（实施阶段发现，补充 [ADR-0002](0002-bm25-over-vectors.md)）

> **读之前先看 [ADR-0000](0000-lineage.md)**：本 ADR 的论证材料来自本项目的前身（一个团队技术知识库）的实测，数字与例子刻意未改写。**决策本身至今有效。**

## 背景

[ADR-0002](0002-bm25-over-vectors.md) 决定用 BM25 + jieba 做纯正文检索。
实施后在真实语料上抽样验证，暴露三个具体失效模式：

1. **文件名语义丢失**：查询"固件指令集"命中不到
   `raw/Company_Facts_And_Status/固件指令集.md` —— 那是一张 85 KB 的纯表格，
   正文里根本不出现这四个字，语义完全在文件名上。
   同类问题还有会议日期（只存在于目录名 `26-08-04-…`）与芯片型号
   （只存在于目录名 `EFR32BG21A010F768-固件与客户端开发文档`）。
2. **长标识符不可部分匹配**：jieba 的搜索模式只对中文长词做二次切分，
   字母数字串始终是一个整体。用芯片系列名 `EFR32BG21` 检索，
   命中不到完整型号 `EFR32BG21A010F768`。
3. **日期被拆成高频碎片**：`26-08-04` 被切成 `26` / `08` / `04`。
   本语料中几乎每个会议目录都以 `26-xx-xx` 开头，这三个碎片的 IDF 被稀释到
   没有区分度，却仍然靠词频把无关文档顶上来；而日期作为整体的语义完全丢失。

## 决策

BM25 的每个 chunk 检索词 = **路径分词 + 正文分词**，并在分词中加入两条规则：

1. **路径入索引**（`tokenize_path`）：把 `/`、`-`、`_`、`.` 替换为空格后分词。
   路径分词按文件缓存，同一文件的上百个 chunk 不重复切分。
2. **长标识符展开**：对长度 ≥ 8 的纯字母数字 token，额外发出其中包含的领域术语
   （来自 `DOMAIN_TERMS` 表）。影响面被限制在型号 / 协议名这类标识符上。
3. **日期原子化**：先用 `\d{2,4}-\d{1,2}-\d{1,2}` 把日期串**从待分词文本中摘出**，
   只作为一个完整检索词发出 —— 不发出 `26`/`08`/`04` 碎片。

同时维护一份 `DOMAIN_TERMS` 领域词典（`EFR32BG21`、`LESC`、`BtleJack`、
`DXToy`、`Tophy`、`重放攻击` 等），在 jieba 初始化时 `add_word`，
防止专有名词被默认词典切碎。

## 理由

三条规则都不是通用检索优化，而是**针对本语料实测失效模式的定点修复**，
每条都有对应的失败样本。代价合计约 30 行代码与一张词表，无新增依赖。

不采用"把文件名拼进正文再切块"的做法：那会污染返回给调用方的片段正文，
让 LLM 看到并不存在于原文中的内容。路径只进检索词，不进返回内容。

## 后果

- 可以直接用会议日期、芯片型号、文档名来定位材料，这是本语料最自然的检索入口
- 抽样验收从"文件名类查询全部失败"改善到 6/6 全部命中有效证据
- `DOMAIN_TERMS` 是需要随语料演进维护的表；新增重要术语时应同步补充
- 路径分词会让同一文件的所有 chunk 共享一组路径词。这是有意的：
  它表达的正是"这些块来自同一篇材料"
