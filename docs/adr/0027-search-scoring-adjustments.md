# ADR-0027 · 检索打分调整：时间加分、路径命中加分、分词前去除 wikilink

**状态**：已采纳并实施 · 2026-09-29（未发布）
**补充**：[ADR-0012](0012-path-and-term-tokenization.md) 的路径词放大词频副作用、
[ADR-0013](0013-term-presence-over-positive-score.md) 的 `score` 口径、
[ADR-0019](0019-index-cache-incremental.md) 的指纹组成

> 案例已做匿名化处理：专题名、source 名与目录名均为虚构的通用写法，排名数据来自真实语料的离线复现。

## 背景

多个 AI 检索某专题的"设备安全方案"时，拿到的都是会议纪要目录下已过期的会议稿；当前权威的结论汇总
`设计/设备安全方案总览.md` 排在第 16 篇文档之后，前 12 篇全是会议稿。用本项目的分词与 BM25 代码在真实语料上
离线复现，排序与线上一致。根因有三层：

1. **查询词失去区分度**："设备 / 安全 / 方案"出现在该 source 过半的 chunk 中，三个词的 IDF 同时落到
   `BM25Okapi` 的 epsilon 下限，排序退化为纯词频比较。
2. **会议稿的词频被放大**：会议目录名 `26-07-xx-设备安全问题分析与解决方案-…` 经路径分词进入该文档
   **每个** chunk（ADR-0012）；正文里大量指向会议稿的 wikilink 又把这些词重复几十次。
3. **引擎没有新旧信号**：语料作者在语料里写明"会议目录只读历史，不作为最终决策依据"，但检索无从得知。

约束：只返回证据、不替调用方下结论（[ADR-0003](0003-evidence-not-answers.md)），历史文档只能降低分数，不能排除；
命中判定保持"chunk 含至少一个查询词"（ADR-0013）；配置修改重启生效（[ADR-0017](0017-config-file-and-cli.md)）。

## 决策

`config.json` 新增 `scoring` 子对象，集中放 BM25 之外的打分调整。全局一份，每个 source 可放同构的
`scoring` 对象**按字段覆盖**全局值，没写的字段继承全局值。默认开启：

```json
"scoring": {
  "recency_window_days": 30,
  "recency_bonus": 10,
  "path_match_bonus": 5,
  "strip_wikilinks": true
}
```

返回的 `score` = BM25 分 + 路径命中加分 + 时间加分（均为加法）。

| 配置项 | 默认值 | 生效时机 | 规则 |
|---|---|---|---|
| `recency_window_days` / `recency_bonus` | 30 / 10 | 查询时 | `recency_bonus × (1 − 年龄/窗口)`，按文件 mtime 线性衰减；窗口外加 0；mtime 在未来按年龄 0 计，不超过上限。任一为 0 即关闭 |
| `path_match_bonus` | 5 | 查询时 | 查询按空白拆词并转小写，**每个词**都是 source 内相对路径（含目录与文件名）的子串时，整篇文档的所有 chunk 加一次固定分；只中部分词加 0，不按出现次数累加 |
| `strip_wikilinks` | true | 建索引时 | 分词前把 `[[...]]` 整段（含别名）替换为**等长空格**再分词；切块区间、chunk 序号、片段与原文不变 |

实现要点：

- 有效值在配置层合并，挂在每个 `Source` 上；快照持有"source 名 → Scoring"，四个构造点都传入。
- 加分只作用于已按 ADR-0013 判定的命中，排序键为 BM25 分 + 加分；命中集合、`total_matched`、
  每篇文档最多 2 个结果位的规则都不变。每篇文档的加分只算一次。
- 等长遮罩让跨切块边界的链接也能完整去掉，不会残留半截链接文字。
- 缓存指纹纳入 `strip_wikilinks` 的全局值与"与全局不同的 source 覆盖"；查询时加分不进指纹。
  新增一个用默认值的 source 不作废缓存。旧缓存指纹里没有这一项，升级后自然不同，无需递增 `CACHE_FORMAT`。

## 理由

离线实测（真实语料，数字为目标文档的排名）：

| 配置 | 设备安全方案→总览 | 设备安全 决策→总览 | …最新→总览 | 决策→推荐方案完整版 | 26-07-15 会议结论 | 历史方案细节 | 推荐方案完整版 | 场景覆盖表 |
|---|---|---|---|---|---|---|---|---|
| 修复前 | 16 | 47 | 23 | 27 | 1 | 6 | 16 | 3 |
| 默认（30 天 / +10，路径 +5，去 wikilink） | 1 | 10 | 2 | 3 | 1 | 9 | 1 | 1 |

- **路径命中加分**：从 +3 到 +30 排名完全一样；+3 是让文件名类查询全部排第 1 的最小值，取 +5 留余量，
  同时远低于常见 BM25 分数（几到二十几）。
- **时间加分**：+30 虽让原问题排第 1，但把"26-07-15 会议结论"从第 1 挤到第 20；+10 是平衡点。
  90 天窗口在该语料上力度偏弱（"设备安全 决策"只到第 27），且历史文档越旧越容易被近期文档压过，改为 30 天。
- **去除 wikilink**：稳定的小幅提升；保留别名与整段去掉效果相同，选择整段去掉。

## 备选与取舍

- **按目录配权重**（如会议目录 ×0.7）：实测最有效，也不依赖 mtime；但每个语料都要人工维护目录规则。不采用。
- **文档 frontmatter 标 `status: superseded`**：粒度最细，但要逐篇标注，外部同步来的文档无法标。不采用。
- **时间加分用乘法 `×(1+系数)`**：随查询分数量级缩放、对历史查询最安全，但力度最弱。不采用。
- **路径分词只进首 chunk**：每种组合下都比现状差，且与 ADR-0012 冲突。不采用。
- **文件名必须与查询完全相等**：匹配不到"……总览"这类文件名，解决不了问题。不采用。
- **按命中词比例给路径分**：把常见词的分送给所有会议稿，等于给旧文档加分。不采用。
- **结果里返回 `updated_at` 或降权标记**：让调用方自己判断新旧；不改响应结构。不采用。
- **只改语料**（会议目录改名或移出索引）：历史就搜不到了，别的语料也会遇到同样问题。不采用。
- **路径命中也提到 +10**：可保证路径完整命中始终压过时间差、真实语料排名不变；选择保持 +5，接受下述取舍。

## 后果

- 默认开启，所有用户升级后排序都会变化；升级后首次启动全量重建一次索引。想保持旧排序：
  `"scoring": {"recency_bonus": 0, "path_match_bonus": 0, "strip_wikilinks": false}`。
- `search` 响应字段不变，`score` 的数值含加分，工具描述不专门说明（省 token）。`/health` 的配置摘要报告有效打分配置。
- 配置可直接编辑 JSON，也可用 `config.py`（[ADR-0017](0017-config-file-and-cli.md)）：`--scoring 字段=值` / `--reset-scoring 字段|all`，
  全局用 `config edit`，单个 source 用 `source edit <名称>`，写法相同。
- **mtime ≠ 内容日期**：批量改动、同步、拷贝都会刷新旧文档的 mtime（该语料就有一次整体批量改动）。
  这类 source 可设 `"scoring": {"recency_bonus": 0}`。
- **加分是固定值**，不随查询的分数量级缩放；建议加分上限不超过常见 BM25 分数的一半（约 3–10）。
- **短而常见的查询**会让同一 source 里大量文档同时拿到路径加分，可能让该 source 整体排前。
- **时间上限（10）大于路径加分（5）**：近期改过、又含任一查询词的文档，可能排在"路径完整命中"的旧文档之前；
  按日期 + 标题查历史时，目标可能排第 2。回归测试断言历史目标在前 2。
