# ADR-0020 · 挂载盘掉线：盘根不可达才算掉盘，掉盘不更新不删除

**状态**：已采纳并实施 · 2026-09-24
**修订**：[ADR-0015](0015-workspaces.md) 的"目录不存在即启动失败"
**术语**：2026-09-24 起 workspace 更名为 source，见 [ADR-0023](0023-rename-workspace-to-source.md)；本文保留原措辞。

掉盘时扫描会得到 0 个文件，旧逻辑据此重建，整个 workspace 从检索里消失；启动时盘不在则直接报错退出。
现在以 workspace 所在**盘根**（`Z:\`、`\\server\share\`）能否访问来判定掉盘——
不以目录是否存在判定，因为目录可能是被人删除了。掉盘期间该 workspace 的索引与缓存
原样保留、不更新不删除，其他 workspace 照常；get-document 从缓存返回全文并标 `stale`；save 拒绝；
盘恢复后下一次轮询自动恢复。盘在但目录不存在按删除处理，索引与缓存一并清除。
两种情况启动时都只警告、不失败；路径拼错改由 CLI 添加时校验与 `/health` 的 `available` 发现。
名称非法、重名、重叠仍启动失败。

**修订 · 2026-09-24**：POSIX 上挂载点盘根恒为 `/`，盘根判定永远通过。Linux 改为对
挂载点做一次带 3 秒超时（外置 `timeout(1)`）的 `ls` 探测，目录不可达时再探父目录以
区分掉盘与目录被删；超时后不等待遗留子进程，它退出前不再起新探测。Windows 维持
盘根判定不变。hard mount 下子进程可能陷入不可中断睡眠，探测线程不被拖死是本修订的动机。
