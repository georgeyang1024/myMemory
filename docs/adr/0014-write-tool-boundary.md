# ADR-0014 · 写入工具：标识符而非路径，同路径覆盖，异步刷新

**状态**：已采纳 · 2026-09-17（同日修订：写入语义由"不覆盖"改为"覆盖"）
**取代**：[ADR-0006](0006-two-tool-surface.md) 的"2 个工具"、
**修订**：2026-09-24（二）—— "不做增量索引"已被 [ADR-0019](0019-index-cache-incremental.md) 取代。
[ADR-0010](0010-indexed-set-membership.md) 的"只读保证"一节
**修订**：2026-09-24 —— save 新增必填 `workspace`，分类可为空，文件名白名单补充常用半角符号，只读 workspace 拒写；见 [REQUIREMENTS](../REQUIREMENTS.md) 与 [ADR-0016](0016-readonly-by-name-prefix.md)。
**修订**：2026-09-27 —— 写入面继续扩展：新增 `rename`（同 source 改名/移一级分类，目标存在即拒绝）、
`replace`（全文完全字面的 old→new 局部替换）、`merge`（把已存在的一篇并入另一篇并**删除源文件**，
并入段带来源标题与分隔线）与 `delete`（真删）。下文"代码中仍然不存在删除文件的路径，也不存在
重命名或移动的路径"已被取代：这些路径都存在了，但删除类能力（delete 真删、merge 删源）藏在
一个默认关闭的断路器后面——config.json 的 `allow_mcp_delete`，关闭时连工具都不注册，
写入层再用同一开关兜一道闸（writer.py `_require_delete_enabled`）。

## 背景

服务由只读的团队知识库改造为**个人记忆库**后，多了一项此前不存在的需求：
让调用方（LLM）把一条值得长期留存的信息写进库里，并让它随后能被检索到。

这推翻了原设计的一条基础前提——"代码中不存在任何写文件路径"
（ADR-0010 的"只读保证"一节）。该前提此前同时承担了两件事：
杜绝语料被意外破坏，以及让免鉴权的暴露面只涉及"读"。两者都需要重新安排。

## 决策

新增第三个工具 `myMemory-save(category, filename, content)`，并在
`src/my_memory/writer.py` 中集中实现，遵守四条约束：

### 1. category 与 filename 是标识符，不是路径

两者都过字符集白名单（`config.is_valid_category` / `is_valid_filename`），
白名单中**不含 `/` 与 `.`**。因此 `../x`、`a/b`、`.`、`.hidden` 这类输入
在语法层就被拒绝，落盘路径只可能是 `root/<分类>/<文件名>.md` 这一种形态。

**不做 realpath、不做前缀比较**——这与 ADR-0010 为读取路径选择的思路同源：
路径穿越、符号链接逃逸、编码绕过在语义上无法发生，而不是"被挡住了"。
`realpath` + 前缀白名单那条路历史上反复出现漏洞，这里不重走。

不接受调用方传完整路径，也是同一个理由：那会立刻把问题变回"如何安全地
校验一个路径"。

### 2. 分类只有一级 —— 这是 MCP 侧的约定，不是记忆库的结构限制

**写入侧**路径形态恒为 `<分类>/<文件名>.md`，"记忆归到哪一类"因此始终是一个
可枚举的有限集合——既便于调用方复用已有分类（用分类名当检索词即可列举），
也避免 Agent 随手建目录、把记忆长成一棵谁也说不清的深树。

**读取侧没有这条限制。** `corpus.scan` 用 `rglob` 递归整个记忆根目录，任意层级
都进索引、都搜得到、都能 `get-document` 读原文。因此：

> **人工操作不受 MCP 与 RAG 约束。** 你在编辑器里想建几层目录就建几层、
> 想怎么组织就怎么组织、想直接改哪篇就改哪篇。索引照收，轮询照更新。
> 一级目录只是"Agent 通过工具写入时"的约定，用来约束 Agent，不是约束你。

这条区分是有意的：约束的目的是让**自动写入**可预测，而不是让人迁就工具。

### 3. 同路径覆盖（upsert）

写入用 `open(path, "w")`：文件已存在即**整篇替换**，不追加、不合并、不改名、
不加序号。工具名为此从 `myMemory-create` 改为 `myMemory-save`——
一个叫 "create" 却会覆盖的工具，对调用方是最糟糕的一类命名。

**初版的决定是相反的**（`open(..., "x")`，同名报错），理由是"免鉴权服务上的
静默数据丢失不可接受"。改成覆盖是明确的设计决定：调用方真正需要的是
"把这条记忆保存成这个名字"，而不是"只在不存在时才保存"——后者会逼出
`xxx-1`、`xxx-2` 这类垃圾文件名，最终反而让记忆库更难维护。

**这个风险是真实的，没有被消除，只能被"看见"：**

- 覆盖不可撤销，服务不做任何备份（记忆库通常也不在版本库里）；
- 因此 `instructions` 与工具描述里都把"**调用前先 search 一次**"写成硬性要求，
  并说明"要在已有记忆上改，先 `get-document` 读回原文再整篇写回"；
- 响应体返回 `created`（新建还是覆盖）与 `replaced_char_count`（被替换内容多长），
  并要求调用方在覆盖时告知用户——这是用户唯一能察觉旧内容已被替换的机会；
- **空正文一律拒绝**，无论新建还是覆盖。否则一次误调用就能清空一篇记忆，
  而这恰恰是最容易发生、也最难察觉的破坏。

~~代码中仍然不存在**删除**文件的路径，也不存在重命名或移动的路径。~~
（2026-09-27 修订：rename / replace / merge / delete 已存在。前者不受开关控制；
merge 与 delete 受 `allow_mcp_delete` 断路器控制——默认关、人工开启、重启生效。）

### 4. 正文原样写入

服务不添加 frontmatter、标题或时间戳。加了就意味着每篇记忆都带一段
调用方没要求、也不知道存在的文本，它会进索引、会出现在检索片段里，且无法关掉。
需要日期、来源、标签的，由调用方自己写进正文——它比服务更清楚该写什么。

### 5. 刷新是异步的

写入成功立即返回，索引在后台线程重建（`IndexHolder.request_rebuild`）。

同步重建会让每次写入都阻塞数秒，且这个代价随记忆库增长而增长。
代价是**新记忆有几秒钟搜不到**，因此必须在工具描述里写明这一点——
不说明的话，模型写完立刻 search 搜不到，会判定写入失败并重试，
于是产生一串 `xxx`、`xxx-1`、`xxx-2` 的重复记忆。

并发请求**合并而非堆叠**：已有重建在跑时不再起第二个线程，只置 pending 标志，
由在跑的那个线程结束后再跑一轮。否则连续创建 N 条记忆会起 N 个线程同时做全量构建，
既浪费 CPU，也可能让先启动的线程用旧语料的结果覆盖后启动线程的新结果。

## 备选方案

| 方案 | 不采纳的理由 |
|---|---|
| 调用方传完整相对路径 | 把问题变回"安全地校验一个路径"，正是 ADR-0010 绕开的那条路 |
| 允许嵌套分类 | 分类名要么做路径解析，要么逐段白名单；且记忆会长成深树 |
| 同名自动加序号 | 静默产生 `xxx-1`、`xxx-2`，调用方以为写成功了两条不同的记忆 |
| 同名报错（初版做法） | 逼调用方换名字，结果同样是一堆 `xxx-1`；"保存"这个动作本就该是幂等的 |
| 覆盖但留备份（`.bak`） | 备份文件会进索引、出现在检索结果里；排除它又要给 corpus 加一条特例规则 |
| 追加而非替换 | 调用方无法表达"这一段写错了"；久了每篇记忆都变成流水账 |
| 服务自动加 frontmatter/时间戳 | 每篇记忆多一段调用方不知道的文本，进索引且关不掉 |
| 同步重建后返回 | 每次写入阻塞数秒，且随库增长恶化 |
| 增量索引（只把新文件加进快照） | 全量重建在当前规模只需数秒；增量要处理删除、重排与 BM25 的 IDF 更新，复杂度不成比例 |
| 再开一个 REST 写入端点 | 多一个入口就多一处要守的边界，而 REST 写入没有已知需求 |

## 后果

- **威胁模型改变**：免鉴权 + 局域网开放意味着任何能连到端口的人现在都能往
  记忆目录里投放文件。这是"可写"这项需求的直接后果，README 的安全说明必须明说，
  部署位置需据此判断。只在本机使用时应设 `MEMORY_HOST=127.0.0.1`
- 破坏性变更：服务名、全部工具名与工具数量都变了，版本号升至 3.0.0；
  写入语义改为覆盖、工具改名为 `myMemory-save` 后升至 3.1.0
- **覆盖的风险由"先 search"这条约定承担**，而约定由 LLM 执行——
  它不是技术保证。真正在意某几篇记忆时，把记忆库放进版本库是唯一可靠的兜底
- `/health` 增加 `rebuilding` 字段，让"刚写完还搜不到"这件事可自查
- 轮询（ADR-0007）的职责收窄为**捕获绕过本服务的改动**——在编辑器里直接
  增删改记忆文件时，服务只能靠轮询发现；经本工具写入的记忆不依赖轮询
