# ADR-0003 · 服务语义：只返回证据，服务端不含 LLM

**状态**：已采纳 · 2026-09-02

## 背景

同团队已有的一个知识库服务（`http://<内网服务器>:<端口>/mcp`）提供
`kb_query(mode=cross_ai)`：服务端起异步 job 调用 LLM 生成答案，配套
状态轮询。是否照搬该形态需要决策。

## 决策

服务只做检索，返回带来源路径的证据片段，由调用方 LLM 自行合成答案。
服务端不包含任何 LLM 调用。消费方明确为 LLM Agent（Claude Code / Codex）。

## 理由

1. **架构冗余**：MCP 协议的设计意图就是把工具结果喂给已存在的 LLM。消费方本身是
   LLM，服务端再套一层是纯粹的浪费
2. **凭据风险不可接受**：服务要求免鉴权局域网开放（[ADR-0010](0010-indexed-set-membership.md)），
   若服务端持有 LLM API Key，等于任何能连上的人都可无限消耗该 Key
3. **复杂度翻倍**：异步答案需要 job 队列 + 状态轮询 + 结果存储
4. **可复现性**：纯检索结果 100% 可复现；生成式答案出错时无法区分是检索问题还是生成问题
5. **与仓库既有原则一致**：`CLAUDE.md` 规定"不允许无来源断言"，服务只摆出来源、
   把判断权留给调用方，正是该原则的服务化表达

## 后果

- 服务无状态、无外呼、无凭据，响应延迟 2 ms
- 非 LLM 客户端（人类通过浏览器）拿到的是片段列表而非答案。`GET /search` 端点
  ([ADR-0009](0009-official-sdk-streamable-http.md)) 满足调试需求，但不面向终端用户体验
