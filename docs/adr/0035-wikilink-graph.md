# ADR-0035 · 关联图：`[[链接]]` 关联，search 附关联文档

**状态**：已采纳并实施 · 2026-10-16（0.7.0）
**修订**：[ADR-0006](0006-two-tool-surface.md) 的 search 返回字段（新增 `related`，不新增工具）

## 背景

检索只能回答"哪里出现了这个词"，回答不了"它还和哪些记忆有关"。记忆之间的关联
本来就存在于正文里：语料大量使用 Obsidian 式 `[[wikilink]]`，但 `strip_wikilinks`
（[ADR-0027](0027-search-scoring-adjustments.md)）只把它们当检索噪声遮掉，关联信息被丢弃。

需求：搜到一个东西时，能知道它关联、指向哪些其它记忆，并顺着读过去。

## 决策

**最小改动：只用显式链接，统一为 `[[...]]`。**

1. **抽取**：建索引时从正文抽出每个 `[[目标|别名]]` / `[[目标#标题]]` 的目标部分，
   记在条目上（`FileEntry.links`）。与 `strip_wikilinks` 无关——遮罩只影响检索词。
   `CACHE_FORMAT` 4→5，升级后全量重建一次。
2. **解析**：快照按需（首次需要时）在**同一 source 内**解析成无向邻接，出链、反链都算关联。
   规则按 Obsidian 习惯：先精确路径，再按文件名/路径后缀匹配；扩展名可省略、大小写不敏感；
   同名多篇取路径最短的，再按字典序。解析不到的链接与自引丢弃。内容签名不变的快照沿用旧图。
3. **输出**：`search` 每条命中附 `"related": [path, …]`，最多 3 篇，无关联时省略字段。
   超过 3 篇时伪随机抽取：种子取自文档版本 `(mtime, size)` 与邻居集合——二者不变就一直返回
   同一组（重启也不变），文档或其关联变了才重新抽。无需额外缓存结构与持久化。
4. **写入**：只在 `save` 的工具说明里提示 AI 在 content 里写 `[[分类/文件名.md]]` 关联同 source 的已有记忆，照抄
   search 返回值、含分类（如 `[[工作/周报.md]]`）——实测只写文件名时，模型常把分类砍掉；
   服务端不自动插链接、不给候选。Obsidian 打开记忆目录即可在图谱中看到同一张图。
5. **开关**：顶层 `link_graph`，系统级，与 `allow_mcp_delete` 同类（改配置重启生效），
   **默认开**。关闭时 `search` 不附 `related`，`search` / `save` 工具说明不含相关段落。
   链接抽取不受开关影响，开关不进缓存指纹，切换不作废缓存。
6. **不跨 source**：链接只在所在 source 内解析，`related` 与命中同 source——多人共用时
   不会越出会话范围（[ADR-0029](0029-single-instance-scoping-and-dynamic-personal-sources.md)）。

## 考虑过的方案

- **提及（正文出现另一篇的文件名）/ 共享稀有词**：能发现未写链接的隐性关联，但噪声大、
  要调参；先不做，等显式链接用起来再评估。
- **知识图谱（实体关系抽取）**：需要 LLM 或模型，违背 [ADR-0002](0002-bm25-over-vectors.md)、
  [ADR-0003](0003-evidence-not-answers.md)。否决。
- **新增 `related` 工具做多跳遍历**：需求只要一跳，且 ADR-0006 要求优先内嵌信息。暂不加。
- **标准 Markdown 链接 `[](x.md)`**：Obsidian 图谱也识别，但两套语法增加解析与约定成本；
  统一 `[[...]]`。
- **跨 source 关联**：多人共用下有越权风险，且 Obsidian 以单个仓库为单位。否决。
- **真随机 + 运行时缓存**：重启后结果漂移，还要维护失效逻辑；确定性种子等价于"缓存到文档更新"。

## 后果

- 工具面不变；`search` 命中多一个可选字段，只含 path，token 开销小。
- 关联质量取决于记忆里写了多少 `[[链接]]`；AI 写入时按说明补链接，人用 Obsidian 补链接。
- 重命名不改写引用它的链接：旧链接变成断链、静默丢弃（与 Obsidian 关闭"自动更新链接"时一致）。
