# ADR-0026 · 刷新只填空位、冷启动抢救掉盘 source、指纹去掉版本号

**状态**：已采纳并实施 · 2026-09-28（0.3.0）
**修订**：[ADR-0019](0019-index-cache-incremental.md) 的"指纹不符即全量构建"与指纹组成、
[ADR-0024](0024-max-cached-docs.md) 中"刷新时新读进来的全文放进缓存"
**补充**：[ADR-0020](0020-mounted-disk-offline.md) 的"掉盘不更新不删除"在全量与冷启动路径上的缺口

## 背景

ADR-0024 之后，全文只存在一个所有 source 共用的 LRU（容量 C = `max_cached_docs`，默认 1000）里，
index.cache 也只持久化这部分全文；条目只有块偏移与分词结果。盘在线时，全文丢了可以重新读盘；
掉盘时缓存是唯一来源。有两条路径会让掉盘 source 丢数据：

1. **运行中全量刷新**：在线文件逐个重读并 `put`，新 key 挤掉最旧的条目；掉盘全文没被重新 put，
   处在最旧的位置，**最先被挤掉**。在线 N 篇时，掉盘全文最多剩 C − N 篇。
2. **冷启动时指纹不符**：`build()` 以空的旧条目调用 `refresh`，掉盘 source 没有东西可以沿用，
   **整个从索引消失**；所有 `agent_mtime` 同时丢失，edited_by 全部变成 scan。

另外，指纹里含 `__version__`，**每次升版本号都会作废缓存**，触发全量构建（网络盘 2–4 分钟），
遇到掉盘时就是第 2 条。

## 决策

- **不钉住，自然淘汰**：掉盘条目在 LRU 里没有任何特殊保护。
- **刷新只填空位、不挤人**：刷新（全量、增量、冷启动构建）新读进来的全文走 `ContentCache.offer`：
  key 已在缓存里就原地更新（不移动 LRU 位置，刷新不算使用）；有空位（或容量为 0，表示不限）就放到末尾；
  满了就不放。真实使用（get-document 读盘、检索取片段）仍按原来的 `put` 进入 LRU。
- **get 失败不进 LRU**：掉盘且未缓存，或读盘失败时，不放入缓存（现有行为，补测试锁定）。
- **冷启动抢救**：仅针对**指纹不符**（格式不符或文件损坏时结构不可信，照旧丢弃）。
  `IndexHolder.start` 读出旧载荷交给 `build`：
  - 在线 source 照旧全量重读，`agent_mtime` 从旧条目沿用；
  - 掉盘 source：旧缓存有全文的，按新配置重新切块、分词，全文按旧的使用顺序先放回 LRU；
    没有全文的，沿用旧条目和旧分词（能搜到，片段为空）；扩展名已不在当前配置里的丢弃。
- **旧分词不特殊处理**：盘恢复后 `(mtime, size)` 一致即被增量复用，等文件改动或手动全量时被动更新。
- **指纹去掉 `__version__`**：剩下 `CACHE_FORMAT`、`chunk_size`、`chunk_overlap`、`extensions`、
  `domain_terms`、jieba 版本。

## 备选与取舍

- **钉住掉盘条目（永不淘汰 / 最后淘汰）**：能保住掉盘全文，但 LRU 只有一个池，钉住等于缩小本地文件
  的可用容量，本地缓存容易被刷走。不采用。
- **全量刷新时把掉盘全文重新插入 LRU**：推演后没有收益——全量刷新照样把在线 N 篇全部 put，
  最终缓存仍是最近放入的 C 篇，掉盘全文的数量不变（最多 C − N 篇），只是从"按使用近期程度"保留
  变成"按扫描顺序"保留，反而更差。根源是刷新整批灌入，所以改为刷新只填空位。
- **抢救时把无全文条目的 mtime 置为 -1**：盘恢复后首轮增量会自动换成新分词；代价是掉盘期间 edited_by
  显示为 scan，多一处特殊值。选择被动更新，保持现有逻辑。
- **抢救格式不符的缓存**：要额外写旧格式的兼容读取。格式变化本来就少见，不做。
- **保留版本号在指纹里**：安全，但每次发版都要付一次全量构建的代价。选择去掉，靠约定兜底（见后果）。

## 后果

- 掉盘全文只会被真实读取自然淘汰，全量刷新不再挤掉它们。LRU 里保留的是"真实用过的文档"，
  不再是"扫描顺序中最后那 C 篇"；无缓存冷启动时保留的是扫描顺序中最先的 C 篇。
- 刷新后第一次读到没被缓存的在线文件时，要读一次盘。
- 指纹不符的冷启动不再让掉盘 source 消失；BM25 里可能暂时混着新旧两套分词，只影响没有全文的掉盘条目。
- **约定**：改了切块或分词逻辑、但配置没变时，必须手动递增 `CACHE_FORMAT`，不能再依赖升版本号来作废缓存。
- 首次从 0.2.0 升到 0.3.0 时，指纹本身就变了（去掉了版本号），走的正是本 ADR 的抢救路径。
