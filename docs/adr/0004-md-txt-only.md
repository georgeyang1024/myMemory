# ADR-0004 · 文件类型：仅 .md 与 .txt

**状态**：已采纳 · 2026-09-02

> **读之前先看 [ADR-0000](0000-lineage.md)**：本 ADR 的论证材料来自本项目的前身（一个团队技术知识库）的实测。**决策本身至今有效**；例子已做匿名化处理，保留形态与量级。

## 背景

[ADR-0001](0001-corpus-scope.md) 确定纳入语料目录的"文本子集"后，实测发现该子集
被少数数据文件严重支配：

| 文件 | 大小 |
|---|---|
| `Research_Programs/<数据采集>/merge_codex/数据分布-补全报告.csv` | 14.0 MB |
| `.../merge2_codex/列表-缺版本.csv` | 2.35 MB |
| `.../merge_codex2/高频条目.csv` | 0.36 MB |

3 个 CSV 独占 16.7 MB，占该子集 "md+txt+csv" 部分的 **83%**。

## 决策

仅索引 `.md` 与 `.txt`。`.csv`、`.xlsx` 及一切非纯文本文档一律排除。
过滤规则写在配置项 `MEMORY_EXTENSIONS` 中，默认 `.md,.txt`。

## 理由

这些 CSV 是"条目 × 属性"的表格数据，不是知识。纳入会产生三重危害：

1. chunk 数从 3,106 膨胀到约 25,000，其中 87% 是枚举字符串噪声
2. 任何含枚举名或数字的查询会被表格行淹没，把真正的方案文档挤出 top-k
3. **IDF 统计被污染**——相关高频词在 14 MB 表格中出现数十万次，彻底丧失区分度

第 3 点是决定性的：污染的不只是被检索到的内容，而是**整个索引的打分基准**。

## 后果

- 剪裁后语料：265 文件 / 2,050,096 字符 / 3,106 chunk
- **接受的损失**：无法查询具体枚举的组合情况
- **待观察项**：`Research_Programs/<数据采集>/agent2/unique_items.txt`（约 70 KB）
  是纯枚举列表数据，按"md/txt 一律收"的规则会进入索引。占比约 2%，影响有限，
  实施后观察其是否干扰检索质量，必要时加入排除列表
