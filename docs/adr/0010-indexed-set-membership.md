# ADR-0010 · 安全边界：索引集合成员校验，不做路径解析

**状态**：已采纳 · 2026-09-02
**修订**：2026-09-17 —— 下文"只读保证"一节已被
[ADR-0014](0014-write-tool-boundary.md) 取代：服务现在有一条写入路径。
本 ADR 的核心决策（读取用集合成员判断，不做路径解析）未变，且 ADR-0014
为写入路径沿用了同一思路。
**修订**：2026-09-24 —— 已索引集合的元素变为 `(workspace, path)`，判断方式不变，见 [ADR-0015](0015-workspaces.md)。

## 背景

服务**无鉴权**（明确需求前提），局域网开放。`myMemory-get-document(path)` 接受
路径参数，是整个设计中唯一的攻击面。

## 备选方案

1. **路径前缀白名单**：`realpath(path)` 后校验是否以 `<root>/raw/` 开头
2. **索引集合成员校验**：直接判断 path 是否在已索引文件集合中
3. 方案 2 + 每 IP 限流

## 决策

采用方案 2。索引构建时本就持有全部已索引文件的精确路径集合
`indexed_paths: frozenset[str]`，`get_document` 只做一次集合成员判断：

```python
if path not in snapshot.indexed_paths:
    return error(...)
```

## 理由

方案 1 这类校验历史上反复出现漏洞：符号链接逃逸、`..` 的各种编码变体、
大小写差异、Windows 短文件名。而方案 2 **根本不存在路径解析这个环节**——
路径穿越、符号链接逃逸、编码绕过在语义上无法发生，而非"被挡住了"。

成本为零：该集合是索引构建的副产品。

附带好处是语义自洽：**能被检索到的才能读全文**，不会出现"搜不到却能读"的怪异状态。

方案 3 的限流保护的是什么？查询延迟 2 ms（CPU 非瓶颈），数据本就是给同事看的。
这是为不存在的威胁付复杂度。

## 资源保护上限

| 限制 | 值 | 目的 |
|---|---|---|
| search 返回条数 | ≤ 20（默认 5） | 防止打爆 LLM 上下文 |
| 片段长度 | ≤ 1200 字符 | 同上 |
| get_document 单次返回 | ≤ 40,000 字符 | 最大文件 125 KB 需 4 次翻页 |
| query 长度 | ≤ 500 字符 | 防止畸形分词输入 |

## DNS Rebinding 保护

实测 SDK 行为：`TransportSecurityMiddleware` 在**未传入** `transport_security` 时
**默认关闭**保护；一旦传入配置对象而 `allowed_hosts` 为空，则**所有请求被拒绝**
（这是一个容易误配成全站 400 的陷阱）。

做成可选开关 `MEMORY_ALLOWED_HOSTS`：

- 留空（默认）→ 关闭保护，任意 Host 头可访问，符合"局域网免授权"原意
- 设为 `192.168.4.234:*,localhost:*` → 开启，可防御"同事浏览器被恶意网页当作跳板"

**默认关闭是有意识的取舍**：部署 IP 未知，误配即全站 400 的风险高于该攻击的实际威胁。
README 需显著标注此开关。

## ~~只读保证~~（已被 ADR-0014 取代）

> **本节记录的是 2026-09-17 之前的状态，现已不成立。**
>
> 原文：服务代码不包含任何写文件路径，语料的不可变性在服务层面通过
> "根本没有写入代码"保证，而非依赖权限配置。
>
> 现状：`src/my_memory/writer.py` 是唯一一条写路径，由 `myMemory-save` 调用。
> 它守的是另一组边界——分类名与文件名是标识符而非路径、只写一级目录、
> 同名不覆盖、不删除不改写。见 [ADR-0014](0014-write-tool-boundary.md)。
> 免鉴权部署下的暴露面因此从"可读"扩大为"可读可写"，这一点 README 已显著标注。

## 后果

- 免鉴权意味着任意局域网用户可读取全部记忆内容，自 ADR-0014 起还可写入。
  这是"局域网免授权 + 可写"这组需求的直接后果，只在本机使用时应设
  `MEMORY_HOST=127.0.0.1`
- `get_document` 路径非法时返回结构化错误并附最相近的已索引路径提示，
  避免 LLM 因路径拼写偏差盲目重试
