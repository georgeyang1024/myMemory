# ADR-0000 · 本项目的由来，以及怎么读之前的 ADR

**状态**：记录 · 2026-09-17

## 本项目从哪来

`myMemory` 由 `ble-sec-kb`（一个蓝牙玩具安全方案的团队知识库 MCP 服务）改造而来。
2026-09-17 的改造做了三件事：

1. 全面改名：包名、环境变量前缀、服务名、工具名、全部对外文案；
2. 语料从团队仓库的 `raw/`（264 篇技术材料）换成个人记忆库 `myDocs/memory/`；
3. 由**只读**变为**可写**：新增 `myMemory-save`，见
   [ADR-0014](0014-write-tool-boundary.md)。

## 怎么读 0001–0013

这些 ADR 记录的是**检索引擎本身**的设计决策——为什么用 BM25 而不是向量、
为什么固定窗口切块、为什么路径要参与分词、为什么索引常驻内存靠轮询更新。
这些决策与语料是什么无关，**至今全部有效**，代码就是按它们写的。

但其中几条的**论证材料**来自当年那份蓝牙语料的实测：具体的文件数、字符数、
chunk 数、CSV 体积、芯片型号切分失败的例子。这些数字**没有被改写**——
改写就成了伪造实测记录，而一条 ADR 的价值恰恰在于它当年是基于什么证据做的判断。

受此影响的有：

| ADR | 其中的实测材料 | 现在怎么看 |
|---|---|---|
| [0001](0001-corpus-scope.md) | 原记录的是"`wiki/` 还是 `raw/`"的取舍 | 已重写，该问题在本项目中不存在 |
| [0002](0002-bm25-over-vectors.md) | 中文技术文档 + 英文专有名词，3,106 chunk | 选 BM25 的理由不变；个人记忆同样是中英混排的短文档 |
| [0004](0004-md-txt-only.md) | 3 个 CSV 占子集 83% 体积 | 只索引 md/txt 的理由不变，例子是当年的 |
| [0011](0011-pinned-deps-both-platforms.md) | 文件名普遍含空格与中文 | 个人记忆的文件名同样如此，结论不变 |
| [0012](0012-path-and-term-tokenization.md) | 芯片型号、会议日期目录的切分失败 | 路径参与分词的理由不变；`DOMAIN_TERMS` 词典里仍保留着这些术语，因为这些主题的记忆确实还在库里 |

[0013](0013-term-presence-over-positive-score.md) 记录的是 rank_bm25 的一个真实陷阱
（常见词的 IDF 为负，按 `score > 0` 过滤会把真实命中整个丢掉），与语料完全无关，
改动那段代码前务必先读它。
